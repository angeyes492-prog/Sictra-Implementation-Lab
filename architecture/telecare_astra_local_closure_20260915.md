## Offline recovery and failure boundary

The signed data archive includes operations, intake, cases, retained source
files, pipeline ledgers/runtime and optional root-local research/design data.
Keys remain separately retained. Inventory binds bytes, key fingerprints and
original absolute path. SQLite backup includes WAL data. Service lock,
symlink/path/size limits and change detection bound the operation; all writers
must be stopped. Uncreated evidence stores remain absent.

Restore requires the original keys and nonexistent original path. Relocation
is rejected because intake identity is path-bound. A STOP marker guards partial
restore; successful recovery records a receipt and stays paused. Existing STOP
is preserved. No encrypted escrow, cloud backup, privileged-attacker protection
or production anti-rollback anchor is claimed. B2/B3 deployments and any data
outside this root retain their own backup boundary.
